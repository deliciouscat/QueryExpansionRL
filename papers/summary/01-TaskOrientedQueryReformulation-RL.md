# 1번째 논문 요약

논문: [Task-Oriented Query Reformulation with Reinforcement Learning](</Users/deliciouscat/projects/QueryExpansion/papers/parsed/1704.04572v4.md>)

저자: Rodrigo Nogueira, Kyunghyun Cho  
핵심 아이디어: 검색 결과가 좋지 않을 때, 검색어를 자동으로 다시 작성하되 검색 엔진의 최종 검색 성능을 보상으로 사용해 강화학습한다.

## 한 줄 요약

기존 검색어와 1차 검색 결과에서 후보 단어를 모은 뒤, 강화학습 에이전트가 “어떤 단어를 추가하면 관련 문서를 더 많이 찾을 수 있는가?”를 학습한다. 세 가지 데이터셋에서 기존 검색어, 전통적 PRF, 지도학습 방식보다 대체로 높은 재현율을 달성했다.

## 문제 설정

긴 질문이나 정확하지 않은 설명을 검색어로 입력하면, 관련 문서에 포함된 단어와 검색어의 단어가 일치하지 않아 문서를 놓칠 수 있다.

예를 들어 검색어가 논문의 제목이라고 할 때, 관련 논문은 제목에 같은 단어를 쓰지 않을 수 있다. 따라서 검색 결과에 등장한 문서에서 유용한 단어를 골라 검색어를 다시 구성하면 더 많은 관련 문서를 찾을 수 있다.

이 논문은 검색어 재작성 과정을 다음과 같은 강화학습 문제로 정의한다.

- 상태: 원래 검색어와 첫 번째 검색 결과
- 행동: 후보 단어 선택
- 환경: 검색 엔진
- 새 검색어: 선택한 단어들을 이어 붙인 것
- 보상: 새 검색어로 검색했을 때 찾은 관련 문서의 비율

즉, 검색 엔진 내부의 랭킹 알고리즘을 직접 수정하지 않고, 검색 엔진을 블랙박스로 취급한 채 검색어를 잘 만드는 방법을 학습한다.

## 제안 기법

### 1. 후보 단어 수집

먼저 원래 검색어 `q0`를 검색해 문서 집합 `D0`을 얻는다.

후보 단어는 다음의 합집합에서 가져온다.

- 원래 검색어에 포함된 단어
- 첫 검색 결과 문서에 포함된 단어

실험에서는 주로 상위 7개 문서에서 앞부분 300개 단어를 후보로 사용했다.

후보 단어가 충분히 일반적인 단어인지, 특정 작업에 유용한 단어인지는 모델이 학습하도록 맡긴다.

### 2. 검색어와 후보 단어 인코딩

각 단어는 사전학습된 word2vec 임베딩으로 변환한다.

- 검색어 전체는 CNN 또는 RNN으로 인코딩
- 후보 단어도 주변 문맥과 함께 CNN 또는 RNN으로 인코딩
- 미등록 단어는 학습 가능한 별도 벡터로 처리

후보 단어의 주변 문맥까지 사용하는 이유는 희귀 단어나 고유명사처럼 단어 자체의 임베딩만으로는 의미를 파악하기 어려운 경우를 보완하기 위해서다.

### 3. 후보 단어 선택 확률

모델은 검색어 표현과 후보 단어 표현을 결합해 각 후보 단어가 선택될 확률을 계산한다.

개념적으로는 다음과 같다.

> 원래 검색어의 의미와 후보 단어의 문맥이 얼마나 잘 맞는가를 보고 선택 확률을 계산한다.

테스트 시에는 확률이 임계값보다 높은 단어들을 선택한다. 학습 중에는 이 확률분포에서 단어를 샘플링한다.

선택된 단어들을 이어 붙여 새 검색어 `q'`를 만든 후, 검색 엔진으로 다시 검색한다.

## 두 가지 검색어 생성 방식

### 독립적 단어 선택

각 후보 단어를 독립적으로 선택한다.

장점:

- 구현이 단순하다.
- 여러 후보 단어를 병렬적으로 처리할 수 있다.

단점:

- 동일한 단어가 중복 선택될 수 있다.
- 검색어가 너무 길어질 수 있다.

### 순차적 검색어 생성

이를 개선하기 위해 LSTM이 한 번에 하나의 단어를 선택하도록 만든 버전도 실험했다.

- 이전에 선택한 단어를 LSTM의 상태에 반영
- 중복 단어를 줄일 수 있음
- 특수 종료 토큰을 선택하면 생성 종료
- 테스트 시 beam search 사용
- 최대 생성 단어 수는 50개

이 모델은 검색어를 훨씬 짧게 만들지만 성능은 일반적인 RL-RNN보다 약간 낮았다.

## 강화학습 학습 방식

REINFORCE 알고리즘을 사용한다.

보상은 주로 `Recall@40`이다.

\[
R@40 = \frac{\text{상위 40개 결과 중 관련 문서 수}}{\text{전체 관련 문서 수}}
\]

학습 과정은 다음과 같다.

1. 원래 검색어로 검색
2. 후보 단어를 생성
3. 후보 단어를 샘플링해 새 검색어 작성
4. 새 검색어로 재검색
5. 관련 문서 재현율을 보상으로 계산
6. 보상이 높았던 단어 선택 확률을 높임

### 가치 네트워크와 baseline

REINFORCE는 보상의 분산이 커 학습이 불안정할 수 있다. 논문은 별도의 value network가 예상 보상 `R-bar`를 계산하게 했다.

실제 정책 업데이트에는 다음과 같은 보상 차이를 사용한다.

> 실제 보상 - 예상 보상

이 방식은 단순히 보상이 높았는지만 보는 것보다 학습을 안정화한다.

### 엔트로피 정규화

초기 학습에서 모델의 선택 확률이 지나치게 한두 단어에 집중되는 문제가 있었다. 그러면 새로운 후보 단어를 탐색하지 못한다.

이를 해결하기 위해 엔트로피 정규화를 추가했다.

- 선택 확률이 한 단어에 과도하게 몰리는 것을 방지
- 다양한 후보 단어를 탐색하도록 유도

## 비교군

논문은 다음 방법들과 비교했다.

### Raw

원래 검색어를 그대로 사용한다.

- Raw-Lucene: Lucene + BM25
- Raw-Google: Google Search

### 전통적 pseudo-relevance feedback

첫 번째 검색 결과에서 단어를 뽑아 검색어를 확장한다.

- PRF-TFIDF: TF-IDF가 높은 단어 선택
- PRF-RM: Lavrenko와 Croft의 relevance model 사용
- PRF-Emb: 원래 검색어와 임베딩 코사인 유사도가 높은 단어 선택
- Vocab-Emb: 검색 결과가 아니라 고정 어휘에서 임베딩 유사도가 높은 단어 선택

### 지도학습 방식

후보 단어를 추가했을 때 검색 성능이 일정 기준 이상 좋아지면 해당 단어를 “유용한 단어”로 표시하고, 이 라벨을 예측하는 분류기를 학습했다.

- SL-FF: feed-forward network
- SL-CNN: CNN 기반 모델

단어가 독립적으로 성능에 기여한다고 가정한다는 한계가 있다.

### 강화학습 방식

- RL-FF: feed-forward network
- RL-CNN: CNN 기반
- RL-RNN: 양방향 LSTM 기반
- RL-RNN-SEQ: 단어를 순차적으로 생성하는 LSTM 기반

## 데이터셋

### TREC-CAR

- Wikipedia 문단 기반
- 검색어: Wikipedia 문서 제목 + 섹션 제목
- 정답 문서: 해당 섹션에 포함된 문단
- 문서 수: 약 350만 개
- 평균 관련 문서 수: 3.6개

예시:

- 검색어: `Sea Turtle, Diet`
- 정답: 해당 문서의 Diet 섹션에 속한 문단

### Jeopardy

- TV 퀴즈 프로그램 Jeopardy의 질문
- 정답 문서: 질문의 답에 해당하는 Wikipedia 문서
- 문서 수: 약 590만 개
- 질문당 관련 문서 수: 평균 1개

이 데이터셋은 질문의 답을 찾는 질의응답 작업에 해당한다.

### Microsoft Academic

- 학술 논문 제목을 검색어로 사용
- 정답 문서: 해당 논문이 인용한 논문들
- 문서 수: 약 48만 개
- 문서 내용: 논문 제목과 초록
- 질문당 관련 문서 수: 평균 17.9개

이 데이터셋은 citation recommendation, 즉 어떤 논문들을 찾아야 하는지 추천하는 작업을 평가한다.

## 평가 지표

- `Recall@40`: 상위 40개 결과에서 관련 문서를 얼마나 많이 찾았는가
- `Precision@10`: 상위 10개 결과 중 관련 문서의 비율
- `MAP@40`: 관련 문서가 결과 목록에서 얼마나 앞쪽에 나오는지까지 반영한 지표

강화학습의 보상으로는 `Recall@40`을 사용했다.

## 실험 결과

주요 결과는 다음과 같다.

| 방법 | TREC-CAR R@40 | Jeopardy R@40 | MSA R@40 |
|---|---:|---:|---:|
| Raw-Lucene | 43.6 | 23.4 | 12.9 |
| PRF-RM | 45.1 | 30.5 | 12.3 |
| SL-CNN | 45.3 | 31.1 | 14.0 |
| RL-CNN | 47.3 | 33.4 | 14.9 |
| RL-RNN | **47.9** | **33.7** | **15.1** |
| RL-RNN-SEQ | 47.4 | 33.4 | 14.8 |
| RL-Oracle | 55.9 | 42.4 | 24.6 |

### 가장 좋은 실제 모델

일반 모델 중에서는 RL-RNN이 가장 좋았다.

Raw-Lucene 대비 Recall@40 개선폭은 다음과 같다.

- TREC-CAR: 43.6 → 47.9
- Jeopardy: 23.4 → 33.7
- MSA: 12.9 → 15.1

특히 Jeopardy에서는 원래 검색어보다 약 44% 높은 상대적 재현율을 기록했다.

### 정밀도와 MAP

RL-RNN의 결과:

| 데이터셋 | P@10 | MAP@40 |
|---|---:|---:|
| TREC-CAR | 7.52 | 20.6 |
| Jeopardy | 2.12 | 8.07 |
| MSA | 7.68 | 4.35 |

기존 방법에 비해 Recall뿐 아니라 Precision과 MAP도 대체로 개선됐다.

다만 모든 강화학습 모델이 모든 지표에서 항상 우월한 것은 아니며, RL의 장점은 특히 검색 결과에서 관련 문서를 더 많이 회수하는 Recall 측면에서 두드러진다.

## 순차 생성 모델의 장단점

RL-RNN-SEQ는 RL-RNN보다 성능이 약간 낮았다.

그러나 검색어 길이는 크게 줄었다.

- RL-RNN: 평균 47단어
- RL-RNN-SEQ: 평균 15단어

따라서 실제 서비스에서는 RL-RNN-SEQ가 더 적합할 가능성이 있다.

- 검색어가 짧아 검색 속도가 빠름
- 중복 단어가 감소
- 검색 엔진에 전달하는 요청이 더 효율적

즉, RL-RNN은 최고 성능 모델이고, RL-RNN-SEQ는 효율성과 운영 측면에서 더 현실적인 모델이다.

## Oracle 실험과 남은 개선 여지

논문은 두 종류의 Oracle을 사용했다.

### SL-Oracle

각 후보 단어의 효과를 완벽하게 알고, 검색 성능을 높이는 단어를 선택한다고 가정한다.

### RL-Oracle

검증·테스트 데이터를 작은 묶음으로 나눈 뒤, 각 묶음에 대해 RL 모델을 과적합시켜 얻을 수 있는 성능을 측정한다.

RL-RNN과 RL-Oracle 사이에는 큰 차이가 있었다.

- TREC-CAR: 47.9 vs. 55.9
- Jeopardy: 33.7 vs. 42.4
- MSA: 15.1 vs. 24.6

이는 제안 방법이 가능성의 상한에 아직 도달하지 못했다는 뜻이다.

저자들이 추정한 원인은 다음과 같다.

- 좋은 단어 선택 전략을 학습하기 어려움
- 검색 엔진이 블랙박스라 상태 정보가 불완전함
- 강화학습 보상의 변동성이 큼
- 후보 단어 수가 제한됨
- 단어 간 상호작용을 제대로 모델링하기 어려움

## 정성적 분석

논문에서 제시한 사례는 이 방법이 단순히 비슷한 단어를 추가하는 것이 아니라, 작업에 따라 서로 다른 단어를 선택할 수 있음을 보여준다.

검색어:

> `Northwestern Connecticut Community College`

학습 작업별 선택 단어:

| 학습 데이터 | 선택 단어 |
|---|---|
| TREC-CAR | `serves american national Winsted accreditation` |
| Jeopardy | `Tunxis Quinebaug Winsted NCCC` |
| MSA | `hospital library arts center cancer center summer programs` |

작업별 차이는 다음과 같다.

- TREC-CAR: 원래 문서와 비슷한 문단을 찾는 데 유리한 표현 선택
- Jeopardy: 답이 될 가능성이 높은 고유명사 선택
- MSA: 논문의 여러 측면을 포괄하는 다양한 개념 선택

따라서 같은 원래 검색어라도 최종 목적에 따라 좋은 검색어가 달라진다는 점을 모델이 학습했다.

## 중요한 한계

### 1. 후보 단어가 검색 결과에 의존한다

후보 단어는 첫 번째 검색 결과에서 주로 가져온다. 따라서 첫 검색 결과가 완전히 엉뚱하면 유용한 단어 자체가 후보에 포함되지 않을 수 있다.

### 2. 검색 엔진을 블랙박스로 취급한다

검색 엔진의 내부 랭킹 신호를 사용하지 않고 최종 결과만 관찰한다. 이 때문에 상태가 부분적으로만 관측된다.

### 3. 학습 비용이 높다

가장 좋은 RL-RNN은 K80 GPU 한 장에서 학습하는 데 약 8~10일이 걸렸다.

다만 추론 시에는 64개 검색어를 배치로 처리하는 데 약 1초가 걸렸고, 그중 약 40%가 실제 검색 엔진 호출에 사용됐다.

### 4. 여러 번의 개혁질 효과가 제한적이었다

이론적으로는 검색 → 개혁질 → 재검색을 여러 번 반복할 수 있지만, 실험에서는 두 번째 검색 이후 추가적인 개혁질이 큰 개선을 만들지 못했다.

### 5. 중립적인 단어도 선택할 수 있다

보상이 관련 문서 증가만 반영하고 불필요한 단어 추가를 직접 벌점으로 주지 않기 때문에, `the`와 같은 일반 단어도 선택될 수 있다.

### 6. 단어 선택을 독립적으로 보는 모델의 한계

지도학습 방식은 후보 단어 각각의 효과를 독립적으로 평가한다. 하지만 실제로는 단어 조합에 따라 효과가 달라진다.

강화학습 방식은 이 문제를 일부 완화하지만, 모든 단어 조합을 효과적으로 탐색하지는 못한다.

## 논문의 핵심 기여

1. 검색어 개혁질을 강화학습 문제로 정식화했다.
2. 검색 엔진을 수정하지 않고, 검색어 생성기만 학습했다.
3. 질의응답, 복합 문서 검색, 논문 인용 검색 등 서로 다른 작업에 적용했다.
4. CNN, RNN, LSTM 기반 모델을 비교했다.
5. 강화학습 모델의 성능 상한을 추정하는 RL-Oracle 방법을 제안했다.
6. 기존 PRF와 지도학습보다 강화학습이 더 높은 Recall을 달성할 수 있음을 보였다.

## 최종 평가

이 논문의 가장 중요한 관점은 “좋은 검색어”를 일반적인 언어적 유사성으로 정의하지 않고, 최종 검색 작업의 성능으로 정의했다는 점이다.

예를 들어:

- 문단 검색에서는 원문과 유사한 단어가 중요하고
- 질의응답에서는 정답 후보가 될 고유명사가 중요하며
- 인용 논문 검색에서는 관련 주제의 여러 측면을 포괄하는 단어가 중요하다

강화학습은 이러한 작업별 차이를 검색 결과의 보상을 통해 직접 학습할 수 있다.

다만 2017년 논문이라 현재의 대규모 언어모델이나 dense retrieval, neural reranking과 비교하면 기술적으로는 초기 단계에 해당한다. 그럼에도 “검색 엔진을 블랙박스 환경으로 보고, 검색어를 행동으로 최적화한다”는 문제 설정은 이후의 학습 기반 검색어 확장 연구에 중요한 출발점이다.
